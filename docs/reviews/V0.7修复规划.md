## 目标与优先级

继续建设“个人读史时可回查出处的时空地图”。本轮解决地图选择歧义、各时期内容不足和首次使用入口，沿用 React、MapLibre、只读 JSON 与现有服务；不迁移数据库。

两报告的优先级含义不同，此处统一：P0 为错误或易造成误解、发布前必须修复；P1 为本轮已承诺的使用与内容改进，同样需要验收；P2 为后续，不作为本轮完成条件。

## 地图约定

山系来源是 Natural Earth 命名概括多边形，不是已测山脊。允许从各分量的局部投影几何主轴和内部截面推导平滑主走向，只作为选中名称后的方向帮助；不跨分离区域强行连线，不把面外沿换名为走向。所有派生数据和详情明确“走向示意，非测绘山脊线”。模糊、不适合或无可靠可读方向的对象保留名称、DEM与解释，不硬造线；高原无须产生山脊线。原始多边形保留作为来源证据，但不作可见块或交互面。

同时显示严格采用上述名称/区域分工。纯自然模式允许河流、湖泊几何点击；山系、高原、海域仅名称/位置入口，无概括面交互。名称按钮需阻止点击穿透。保留实际边界资料年份及近似模型、现代背景标记；秦至隋没有已接入的行政面，不虚构其疆界。

## 内容合同与计数

时间线沿用 `shared/historical-context.ts` 和 `public/data/historical-context.json`，候选新增覆盖为既有地点 xianyang、jinyang、datong、linzi、handan、xiangyang、tongguan、yinchuan、shangdu、quanzhou、dali、dunhuang；确切名单以可核对资料为准。现有35节点，新增12城各3节点意味着至少71节点。

新建 `shared/city-profiles.ts`、`public/data/city-period-profiles.json`，合同为：

```ts
interface CityPeriodProfile {
  id: string;
  placeId: string;
  periodId: string;
  summary: string;
  sourceIds: string[];
  evidence: HistoricalContextEvidence[];
}
interface CityPeriodProfilesData {
  version: string;
  sources: HistoricalContextSource[];
  profiles: CityPeriodProfile[];
}
```

复用现有来源、快照、摘录结构；每个档案只能对应目录已有且当期可见的地点。文字不能将概略参考坐标当古城址证明，迁址、沿革和同名对象需分别解释。目录增关系只在证据充分时协调修改，不为达标批量扩大 `periodIds`。

基线40个独立地点、34事件、10城35节点；11期地点覆盖依次为秦8、汉16、三国17、晋17、南北朝17、隋17、唐37、宋20、元21、明19、清20。本轮优先丰富既有城市；不设新增独立城市配额。验收分别报告独立地点、时期关系、时间线覆盖城/节点、本朝看点数量，绝不把档案或行政面数量当新增城市数量。对评议中“每朝新增关系”的建议采用上述有界内容目标，不机械加点。

## 顺序与验收

计划落盘即通知各组开工：地图P0与自然数据并行；后端先冻结合同并补有源内容，前端依合同实现。内容构建后跑对应数据测试，各组报告实际完成与缺口；主线程整合后跑完整测试与生产构建，再做下面的浏览器检查。V0.6的49项测试仅是基线，不能当V0.7已通过。

| 场景 | 通过条件 |
| --- | --- |
| 同时显示重叠点击 | 秦岭名选秦岭，黄河名选黄河，青海湖名选湖；河线/湖面/原山系内部与边缘点击选择行政区或明确无数据；城点选城，无双选。 |
