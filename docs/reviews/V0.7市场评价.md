# V0.7 市场评价

评估日期：2026-09-24；基线：V0.6.0。方法：只读核对本地说明、数据和代码。本次未做访谈、问卷、竞品实测或流量分析；没有真实市场规模、付费意愿与留存数据。以下明确区分事实与判断，不把模拟评价称为实际用户研究。

**定位判断：适合做个人读史时随手查的、有出处的时空地图。** 下一轮应优先解决操作冲突、各时期内容不足和新手入门，再考虑传播与商业化。

## 证据与价值

- **事实**：[README](../../README.md)明确个人非商业本机使用；已有时期选择、古今双名、历史行政资料、事件和来源回查。区别于单看纸图或单读条目的潜在价值是把这些线索连接起来；这是功能类别比较，未证明相对具体竞品具有独占优势。
- **事实**：[catalog](../../data/catalog.json)实际为11个时期、40个独立地点、34个事件。分期可见地点依次为秦8、汉16、三国17、晋17、南北朝17、隋17、唐37、宋20、元21、明19、清20；唐有14个事件，其他时期各2个。地点跨期复用，数量不能相加。12,111条行政面也不能宣传为万座城池。
- **事实**：[历史地理内容](../历史地理与城市大事记.md)另有8条地理条目、10城35个大事记节点。来源快照与逐字摘录可回查，但百科概述、书目参考、原始文献和古址考证的可信程度并不相同。
- **事实**：[自然图层](../../src/components/PhysicalGeographyLayer.tsx)目前画山系/高原面，并在both模式查询自然图形点击；[来源说明](../自然地理交互范围与来源.md)确认其为1:1000万命名概括面。说明虽准确，视觉仍容易让人误认为精确山体边界。

**目标人群假设**：核心是阅读史书、地方史时需要查古地名和附近山河的个人爱好者；学生和教师可作辅助读图。现阶段不适合承诺专业古址定位、逐年疆界复原或完整历代城市数据库。目标人群规模及付费需求尚未验证。

**内容判断**：地图视觉丰富度高于可持续阅读的内容厚度。唐代最充实，其他时期容易显得只是少数地点改名。内容扩充应同时增加当期名称依据、城池作用与简短本朝看点，不能只加点数或给每个地点复制所有时期。

## 传播、留存与成本判断

再次使用更可能来自“读到新地名来查”和“继续查看城池沿革”，这是待验证假设。先让新手独立完成一次查找和来源回查，比新增动画、积分或社交功能更贴合当前用途。没有证据可推断留存或付费提升。

技术上，现有只读JSON与MapLibre足以支持下一批个人地图内容，没有先换数据库或云服务的必要证据。本地`public/data`约234.4 MiB，其中边界158.5 MiB；这不是首屏下载量或实测加载时间，应测量后再优化。持续成本主要来自时期名称、坐标角色、来源与迁址复核。

**排期假设，非报价或实测工时**：交互规则及引导约2–4工程人日，回归与说明约1–2人日；内容投入单列，先完成5–10条样本并记录采集/复核耗时，再估算全批。不能把代码完成等同内容考证完成。

个人本地迭代无需增加外部发布流程；若未来公开商业分发，[CHGIS](../CHGIS边界接入.md)、[GADM](../古今地名对照与简体字.md)和[原图](../../public/data/atlas/manifest.json)已有明确限制或授权不确定项，需另定可分发数据方案，不能直接沿用当前包。

验证建议：让少量未参与开发的自愿体验者尝试“查一个新增城池”“both模式查黄河后选择附近行政区”“找到事实出处”“重开引导”，记录实际失败位置和耗时。小样本只能发现问题，不代表市场需求；本次尚未进行这些测试或联系任何人。
