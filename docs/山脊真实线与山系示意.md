# 山脊真实线与山系示意

本轮新增独立的现代山地记录图层：OSM `natural=ridge`山脊、`natural=arete`刃脊、`natural=cliff`陡崖的完整way，以及有来源名称的`natural=peak`节点。真实线指来源中确实存在的线记录，不表示本项目已实地测量或独立核实其定位精度。

## 能看到什么

采集区为秦岭与关中南缘、太行山地区、祁连山地区、天山地区、川西山地，较大区域拆为多个查询框。查询矩形仅说明取数范围，既不画成地图边界，也不认作山脉范围。发布清单为`public/data/mountain-detail/manifest.json`，核验结果为`data/evidence/mountain-detail/validation.json`；最终数量以这两份实际生成文件为准。

2026-09-25已完成全部22个查询框，去重后共**14,330个对象**，其中山脊8,940条、刃脊54条、陡崖1,746条、命名山峰3,590个。3,355个对象有来源中文名；其他名称在原始记录中保留。22个发布分包压缩合计1,684,801字节。去重对象按所选来源归属分区统计，重叠查询不会重复计数：

秦岭资料已显示明显限制：大部分山脊没有名称，命名的线又包含陡崖、天坑壁等不同类型。取得的命名山脊包括滚木岭、南羊山大脊、南羊山二脊；太行有沾岭山记录，天山有腾格里山脊和子午脊。它们仍是局部源对象，不能统一冠成“秦岭主脊”，也不能保证连续勾画整条山脉。无名线保留可见、可点击的原形状，详情显示OSM编号；没有已核对中文名的对象不按拼音猜名。

线分级显示：图上线长30千米以上从6级、10千米以上从7级、2千米以上从8级、其余从9级显示；陡崖至少9级。来源标注4000米以上的命名山峰从6.5级、其他命名山峰从8级显示。这是阅读密度规则，不代表重要程度或历史等级。

在“山川”或“全部”模式可以点击线本身、山峰点或名称，查看类型、原始标签、OSM编号/版本、来源链接。来源`ele`明确为数字或米单位时显示米值；无法确认单位的原值原样展示。线长按原始顶点间球面距离求和，表示水平图上线长，不等于地表步行距离、山脊实际三维长度或整条山脉长度。

## 与原秦岭走向示意的区别

原`public/data/mountain-directions.geojson`中的秦岭等山系走向，由Natural Earth命名多边形内部截面推导，是便于定位名称的制图参考。它不是测绘山脊、山体范围、分水岭或登山路线，不能因为一条线看起来连续就据此推导这些含义。

新增图层没有使用原命名多边形、示意中轴、山峰连线、缓冲区、凸包或平滑后的替代线。每条发布LineString逐顶点等于被选中OSM way的完整geometry，并核对节点数量相同；不因查询框边缘裁掉线的一部分。点始终来自原始peak节点，绝不连成山脊。两类资料都不是唐代山地形态的考据复原。

## 接入契约

独立组件`src/components/MountainDetailLayer.tsx`接受：

```ts
{
  map: MapInstance | null;
  ready: boolean;
  enabled: boolean; // 父地图仅在唐代启用
  mode: MapInteractionMode; // cities | mountains | rivers | all
  controlsContainer: HTMLElement | null;
  onChoose: () => void;
  onFocus: (points: [number, number][], maxZoom?: number) => void;
  resetKey: string;
  onLoadedFeatureIds?: (ids: string[]) => void;
}
```

启用期间，山脊/刃脊/陡崖线和基础山峰圆点在所有模式保留，按缩放分级；标签、搜索、点击命中及详情仅在`canInteract(mode, "mountains")`成立时出现。切换到其他模式会清除选择，隐藏透明命中层。数据按实际包边界与视野加载。

`onLoadedFeatureIds`在视野中已加载原始对象ID变化时触发，停用或卸载时传空数组；父地图据此在唐代细节层排除重复山峰的点与标签。此回调不依赖交互模式，避免切模式时重复峰重新出现。

`shared/mountain-detail.ts`导出`mountainDetailHitLayerIds`：`mountain-detail-line-hit`、`mountain-detail-point-hit`。组件先调用共享`findNaturalMapHit(map, event.point, mode)`；仅在其返回本组件图层时处理，再调用`event.originalEvent.preventDefault()`及`onChoose()`。其他自然图层和行政区也使用同一仲裁，确保“全部”模式中同一次点击不会打开两份详情，不依赖事件监听器注册顺序。

## 来源保存与重建

```sh
python3 scripts/fetch-mountain-detail.py
python3 scripts/build-mountain-detail.py
npx tsx --test server/mountain-detail.test.ts
```

采集脚本最多两个并发请求；默认复用已核验快照，`--refresh`明确重新抓取。原始Overpass JSON以确定性gzip无损保存，另存查询文本、查询框、抓取时间、OSM基准时间、来源署名、ODbL许可和压缩/解压后SHA-256。即使源查询返回空集合也保留该结果，不生成占位山脊。

构建脚本全局按OSM type/id去重。相同版本的重复对象必须有相同几何和标签；不同版本保留较高版本并记入报告。发布GeoJSON分包压缩，保留原geometry和tags；只对显示名称进行繁简转换，原始名称不改写。

自动检查逐条比对发布线与原始完整way、节点坐标、标签、版本、来源哈希、全局ID唯一和包范围。它证明资料未被本项目编造或替换，不证明OSM本身没有测绘错误。浏览器的模式切换、图层排序与行政命中优先级由主任务整合后实际验证。

本轮山地专项两项全量检查通过，`npx tsc --noEmit`通过；严格构建重复执行后，22个发布包、清单与核验报告共24个文件哈希全部一致。`manifest.acquisition.complete=true`、`missingTiles=[]`。采集中的服务超时已通过重试补齐，没有以空数组替换失败查询；天山最东侧北框的实际空响应按原结果归档。

## 四模式与重复峰交互复核

2026-09-25独立检查了父地图、自然概览、历史河道、唐细节、山地和行政边界的渲染与点击逻辑。四种模式不从基础数据中移除河湖、治所、山脊或山峰点；模式控制名称、点击权限和选中详情。行政层仍按缩放自动分级，其总开关独立于四种点选模式。此项为代码路径核查，浏览器视觉结果另记主验收记录。

完整扫描两个清单引用的分包后，共找到**194个同OSM ID的重复峰**。194组坐标全部逐值相同；唐细节中峰的`minZoom`全部为10，山地层中对应值全部为8，唐细节包的加载阈值也全部为10。因此当前数据中，山地层报告已加载峰ID后，替代点会早于唐细节的显示阈值出现，不存在因两层阈值不同而漏点的情况。以后调整任何一层阈值时，应重新核对该关系；不能把“已加载”永远等同于“已显示”。

检查发现唐细节的基础点已去重，但搜索仍返回这些峰，导致选择后缺少本层高亮；主任务已将同ID峰从唐细节搜索排除，统一使用山地入口，并为唐细节增加独立选中高亮源，使先选中的峰在山地包加载后仍有明确高亮。

各画布点击处理都调用同一`findNaturalMapHit`。当前顺序为历史黄河、实际山脊/山峰、唐细节河湖/峰、已选山系示意、概览河湖；各模式先过滤允许类别，“全部”中有具体自然对象命中时行政面直接让出点击。命中层不存在时会跳过，山地命中层在不允许交互时隐藏，基础线与峰点保留。
