# 唐代放大地图细节数据

本批只新增真实来源数据、构建脚本、类型和校验，不修改既有 104 个精选城镇、行政区面或主地图组件。入口是 `public/data/tang-detail/manifest.json`，共享类型为 `shared/tang-detail.ts`。

## 可显示的历史点

实际下载官方 CHGIS V6 Time Series County Points 与 Prefecture Points 的 UTF-8、WGS84 点图层。两份 ZIP 的 MD5 与官方 Dataverse 元数据一致；使用原始 SHP POINT，未把行政区多边形中心生成为居民点。

| 资料年份 | 县级层记录 | 府级层记录 | 可显示合计 | 内部坐标冲突、暂隔离 |
| --- | ---: | ---: | ---: | ---: |
| 741 | 1,393 | 332 | 1,725 | 124 |
| 742 | 1,393 | 332 | 1,725 | 126 |
| 755，默认 | 1,365 | 317 | 1,682 | 127 |

755 年县级层中，1,296 条原分类为“县”，另有城、羁縻州、羁縻县、赕等；府级层也含不同单位。层级是源数据分组，不表示这些点全部属于唐朝直接管辖。范围来自官方时序资料，可显示点约在东经 94.52—122.08、北纬 18.31—40.35 之间；不能据此声称覆盖整个唐朝或全部西域城镇。已有精选西域入口继续保留。

筛选规则是原始 `BEG_YR <= year <= END_YR`，与官方字典“结束年为最后有效年”的说明一致。每点保留起讫年、年代精度规则、原始分类、今地说明、来源定位代码及完整原始字段。755 年显示记录中，653 条起始年代规则为空或未定义，10 条按跨朝代时段约定，11 条按朝代约定；不能把年份筛选理解为每点都已精确核定到 755 年。CHGIS 官方也明确说明 1350 年前仍存在空间覆盖缺口。

坐标审计发现：755 年 105 条县级记录、22 条府级记录，原 SHP 点与同条 DBF 的 `X_COOR/Y_COOR` 相差超过 0.02 度，少数达到数百公里。已经独立确认 DBF 与 SHP 数量一致、没有删除记录、直接记录索引一致，差异不是读取时错位产生。例如长社县源 SHP 坐标在陕县附近，而经纬度属性在许昌附近。没有任选其中一方修补；这 127 条保存到 `withheld-coordinate-conflicts.json`，不进入默认地图。

其余坐标保留官方点几何，仅将浮点输出保留至小数点后六位。0.02 度是内部冲突筛查阈值，不是古址精度承诺。源点即使内部一致，也未经本项目独立考古核验。

县级点建议从 zoom 7.2 显示，府级从 zoom 6 显示；前端还可按视野与标签碰撞控制密度。三个资料年份各保存独立 GeoJSON，默认清单只指向 755 年。

## 现代水系、山峰与山口

通过实际可用的 Overpass 公共接口，下载六个区域中的 OpenStreetMap 记录：河流、溪流、水渠、运河、水面多边形、山峰及山口。保存完整原始响应、查询语句、OSM 数据时间、实际获取时间和每条原始标签。

跨区域按 OSM 类型和 ID 去重后，交付 **178,372 个几何要素**：水面 107,453，河段 16,844，水渠或运河段 28,517，溪流段 18,949，山峰 6,509，山口 100。这是记录和河段数量，不能当作互不相同的完整河流数量。水面包括小塘、水库及现代人工设施。

现代数据统一设置 `modernReferenceOnly: true`，并为每个要素提供可直接打开的 OSM node/way/relation 链接。名称优先使用源中文名称，编辑显示转简体，原始标签保留不变。没有根据现代水面推断唐代地貌，也没有通过加宽线条或缓冲区虚构河面。

河线保留原始全部坐标，不做平滑与概括；水面只按原成员线的精确公共端点拼合完整内外环，保留岛屿与孔洞。缺失环、无法闭合或无效面暂不显示，原因逐条保存在转换报告。没有补画缺口、拓扑修补或猜测边线。

## 按缩放与视野加载

现代数据保存为 **296 个 GeoJSON gzip 包**：

- 16 个概览包从 zoom 8 加载，包含主河段及较大水面。
- 280 个局部包从 zoom 10 加载，按约半度经纬网组织溪流、水渠、小水面、山峰和山口。
- 每要素还有 `minZoom`：细小水面通常从 zoom 12 显示；源 OSM `peak` 点不是山系范围多边形。

一个局部包由要素标注锚点分组，几何保持完整，不沿网格切断。`modernRegions[].bounds` 是实际包内几何范围，用于视野相交加载，不是完整覆盖区域。`modernCoverageRegions` 则保留原始六个查询范围，并列出所有与该范围相交的 zoom 8 主包；列表包含去重后归属于相邻区域的包。只有必要主包全部加载成功，前端才可将该查询区作为覆盖范围处理。查询完成表示响应无错误，并不保证 OSM 已调查该区所有水系。

前端可按 `.geojson.gz` URL 获取 ArrayBuffer，经浏览器 `DecompressionStream("gzip")` 解压再解析 JSON，适用于静态 Vite 与生产文件服务，不依赖自定义压缩响应头。地图已加载的全局 OSM ID 可用于进一步避免重复。

本批公开目录约 **63.11 MB**，其中现代 gzip 包共 **55.57 MB**；来源证据约 **90.66 MB**，合计新增数据约 **153.8 MB**。最大的现代包压缩后 **2.30 MB**，所有包解压后小于 8.1 MB；最大的证据文件为 28.65 MB。原始响应保留无损 gzip，并分别保存压缩文件与解压内容的 SHA256，仓库没有超过 100 MB 的新增文件。

## 构建、验证与来源条款

离线构建和验证使用已有的 GIS Python 环境：

```sh
/tmp/map-chgis-runtime/bin/python scripts/build-tang-detail.py
/tmp/map-chgis-runtime/bin/python scripts/validate-tang-detail.py
npx tsx --test server/tang-detail.test.ts
```

新环境需要 `pyshp`、`shapely`，构建同时调用项目中的 `opencc-js`。三个 Node 测试全部通过，覆盖原始 ZIP/SHP/DBF 逐点比对、时段与冲突隔离、压缩及原文双哈希、包大小、坐标有效性、包覆盖清单、简体名称、全局 ID 唯一性。独立 Python 验证逐条比对全部 **178,372** 个现代要素：点和河线坐标序列等于原始记录；水面每条边的集合与原 way 或 relation 成员边集合完全相等，且面有效。结果在 `modern-geometry-validation.json`。

重新取得来源的可复用脚本：

```sh
python3 scripts/fetch-tang-detail-chgis.py
python3 scripts/fetch-tang-detail-osm.py
```

两者默认复用成功归档。OSM 只有显式传入 `--refresh` 才重新查询；所有构建与正常浏览均不依赖 Overpass 在线可用性。

CHGIS 来源为 [V6 Time Series County Points](https://doi.org/10.7910/DVN/Q9VOF5)、[V6 Time Series Prefecture Points](https://doi.org/10.7910/DVN/WW1PD6) 及 [V6 Data Dictionary](https://doi.org/10.7910/DVN/SNCEAU)。真实许可材料存在差异：县点 Dataverse 页面元数据列 CC0，但随包 README 与府点条款限定学术、非商业使用并限制电子再分发。原文完整保留，本次交付用于已授权的个人非商业本地预览；若公开发布数据，应复核 CHGIS 的实际许可，不仅依据页面 CC0 字段。

OSM 数据采用 ODbL 1.0，须保留 **© OpenStreetMap contributors** 署名与[版权说明](https://www.openstreetmap.org/copyright)。本批提供实际来源与归档，不声称 OSM 是古代水系、经过测绘复核的现状成果，或代表该区域全部地物。

## 现代黄河无名水面的来源关联

后续复核发现，一些标记为 `water=river` 的现代黄河水面没有名称，单靠名称遮蔽现代下游会漏掉它们。另附 `yellow-river-water-associations.json`，不改写现代大包：从 22 条名称全值匹配“黄河”“黃河”“Huang He”“Yellow River”的主河线，检查 6,593 个 `water=river` 面，仅确认 **33 个河面、47 组线面关联**。名称正规化只处理繁简黄字、拼音声调和空白，不做子串匹配；双洎河、上黄河、黄河故道等 92 条近似名称记录不作为现代主黄河依据。

每组关联提供真实中心线顶点坐标、该点的源线索引、面内真实顶点数、正长度线面交集、名称原值以及线面各自的 OSM 链接。顶点必须严格在面内，仅边界接触或没有内部真实顶点的组合不纳入。6,560 个未关联河面保持原状，未关联也不等于证明它们不属于黄河。此表只证明已取得现代 OSM 线面之间的空间关系，不能据此生成历史黄河水面。

前端应在历史河道已经加载的合适下游范围，对这些有证据的现代水面作替代遮蔽。不要全域删除这些 ID，也不要把所有现代河面统一隐藏。审计见 `data/evidence/tang-detail/yellow-river-water-association-audit.json`，保留输入清单与输出表 SHA256、所有主线候选、名称排除及边界接触记录。

```sh
/tmp/map-chgis-runtime/bin/python scripts/build-tang-detail-yellow-river-associations.py
npx tsx --test server/yellow-river-water-associations.test.ts
```

两项回归测试逐条独立检查 47 个真实顶点与原几何索引、所有 33 个水面的严格包含关系、原名全值匹配、8 个已知无名面回归、近似名称排除及审计哈希。
