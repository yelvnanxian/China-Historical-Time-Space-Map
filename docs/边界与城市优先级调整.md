# 边界与城市优先级调整

> V0.4更新：用户已明确个人非商业用途，本轮已实际下载并接入CHGIS与Hartwell图层，同时提供历史地图原图阅读器。本文中的“尚未导入”和等待接入安排为旧版本记录，当前结果以[V0.4验收记录](./V0.4验收记录.md)为准。

日期：2026-09-24。依据用户最新反馈与[历史 GIS 数据来源可行性核查](./历史GIS数据来源可行性.md)。本轮将地图内容的优先级调整为：**扩大可核对的城市覆盖，制作首个有来源的历史范围样本**。

## 本轮明确调整

- 撤下当前手工示意政权多边形及相应边界标签。保留历史时期和实体资料，不再用粗折线、平滑曲线或描得更复杂的任意轮廓充当历史疆域。
- **取消“沿时间，观山河”的播放功能**，不再列为后续必做，也不默认重新加入。时期选择、事件点击和日期阅读仍可作为普通导航保留，后续时间版本首先服务数据筛选与引用。
- 优先补充城市及名称依据，保留用户已选择的古今双名同屏和点击沿革。
- 暂无可用历史边界的时期，只显示已有地点和自然地理背景；界面应明确“历史边界尚未提供”，不显示空图层开关或已绘制疆域的暗示。
- 本文对城市、边界和播放功能的优先级调整，替代此前计划中“继续改良示意色块”“播放作为必做”的安排。

### 最小可交付边界样本的两个具体候选

1. **文件标记为 800 年且公开许可较明确的候选：唐朝一条记录。** 现成文件和几何已经找到；还必须补齐原图/书目与关键边界依据，核实该年代的范围并确认适用许可后，单独作为“800 年历史范围样本”交付。工程接入约 1–3 人日，来源追溯与考据先预留 3–8 数据人日，可能因无法追溯而停止。没有补齐依据前，不以“开放源”名义绕过用户对真实边界的要求。
2. **有正式历史 GIS 时间切片的候选：CHGIS 1820 年江宁地区 1–3 个历史行政范围。** 先执行下节的文件、来源及授权检查。工程约 3–6 人日，许可等待另计；不改称唐朝，也不将历史行政区等同于国家边境或古城轮廓。

目前两个候选都有明确文件/数据入口，也都有尚未解决的条件。下一次边界交付应提供某一个样本的实际数据、出处、年代与权限记录，而不是再次画一幅更细的示意轮廓。

## 首个历史范围样本：1820 年江宁地区的历史行政范围

建议先验证 **CHGIS V6 的 1820 时间切片中，一个府级范围及其相邻记录**，优先查询江宁地区。当前地图已有 1820 年清代截面，能直接检查名称、时间、地点和范围的对应关系。这里的目标是一个可追溯的历史行政区样本，不是全国政权疆域，也不是江宁古城城墙。

| 项目 | 已知事实 / 尚需核实 |
| --- | --- |
| 来源 | [CHGIS V6 官方页](https://chgis.fas.harvard.edu/data/chgis/v6/)，2016 年发布；官方明确列出 1820 时间切片入口 |
| 年代 | 仅以具体文件确认的 1820 年历史行政范围使用；不自动外推到其他年份 |
| 样本范围 | 拟查询江宁及邻接府级记录，约 1–3 个面。当前尚未确认候选文件是否包含这些完整多边形；如只有治所点，先保留为点记录，不从点生成边界 |
| 授权 | 官方写明学术研究免费、不得商业使用、转售或再发布；目前不能视为已获本项目展示和再发布授权 |
| 考据缺口 | 需读取具体图层的制图依据、几何来源、日期解释、比例尺/精度、坐标系和记录 ID；需抽样与其引用地图或研究核对。发布机构可信不等于每条边界已经在本项目完成复核 |
| 接入状态 | **候选样本，尚未导入或获再发布授权**。若不能获得适用授权，停止该候选的发布接入，保留调查结果并更换来源；不为了上线改用任意描边 |

选择 1820 年，是因为现有核查确认了对应的数据入口，而唐代 755—763 年逐年控制区尚未找到可直接采用的资料。如果产品只接受唐代样本，则先补唐代城市与史料中的归属关系，另立边界资料核查任务；不能把 1820 年样本换上唐朝名称。

### 已知来源采集的下一步动作

1. **定位具体文件。** 从已知 [V6 数据目录 API](https://dataverse.harvard.edu/api/dataverses/chgis_v6/contents) 找到 1820 数据集，记录 DOI、版本、文件 ID、文件说明与随附许可；先分清点、线、面和行政层级。把这些结果追加到 `docs/research/` 的核查记录。
2. **形成授权问题清单。** 明确本项目希望本地产品演示、公开展示、缓存转换文件、分发 GeoJSON/瓦片等哪些用途；整理需向提供方澄清的条款。现有研究尚未联系提供方，此处不表示已经获得许可或已经发送询问。
3. **条件满足后取一个面样本。** 保存原始文件、版本、校验值及引用要求；核实江宁记录是否存在及其历史层级。没有面就不做凸包、Voronoi 或现代行政区拼接来补足。
4. **验证坐标与证据。** 读取 `.prj`/元数据，确认原坐标系后再转 WGS84；检查治所与区域位置、邻接和几何有效性。拓扑修复只修文件问题，不改变历史解释；简化用于显示时保留原始几何与处理参数。
5. **制作可审查样本包。** 包含原始 ID、来源版本、有效时间、对象类型、来源地图/研究、许可状态、几何转换日志和未解决问题。区分历史行政管辖范围与实际军事控制区。
6. **通过样本后再扩展。** 先展示 1–3 个有依据的面及来源详情，验证点击、时期过滤和引用；再决定是否扩展到同省或同一时间切片。没有足够依据的相邻区域保留空白。

上述步骤是具体待办，不将“能下载”视为可以直接再发布；无需为了检查一个样本先迁移整个数据库。

### 不采用的捷径

- **Hartwell 742 年模型不作为本轮“真实唐代疆域”替代。** 已读 README 明确其使用 1990 年现代县界为构件构造近似历史范围，并称多处边界表示存在问题、地理来源没有进一步文档；同时元数据 CC0 与随附非商业学术条件存在差异。年代、方法和授权均不满足直接替换 755—763 年边界的条件。
- **TGAZ 优先用于地名和年代线索。** 它不是现成的唐代疆域多边形；其导入 CHGIS V3 等上游资料，需要逐条来源和使用条件核对。
- **禁止把现代行政界套成唐界。** 现代省、市、县、建成区及 Natural Earth 自然地理数据，都不能仅靠重命名、改色或裁剪成为唐代政治范围。

## 两级城市新增排期

**本轮实际新增 12 个唐代城市/州府入口：陕、郑、滑、怀、恒、贝、平原、鄜、潞、邓、许、徐。** 目录总数由 28 增至 40，唐代可见地点由 25 增至 37；专题原有地点集合仍按事件关联定义。新增入口不意味着坐标已经升级为精确城址，也不代表这些名称可直接复用于所有朝代。

现有只读 JSON、搜索、详情和来源模型可以直接承载后续批次，工程不应等待完整数据库或后台。下面是本轮 12 个之后的两级排期，历史名称、可见时期和坐标精度核对单独计算。1 工程人日为熟练工程师全职一天，数据投入和授权等待另外计算。

| 批次 | 有界目标 | 工程安排与投入 | 历史数据核对与依赖 |
| --- | --- | --- | --- |
| **一级：接续小批次，补到 50–60 个入口** | 在本轮 40 个基础上再新增约 **10–20 个**重要州府/城邑入口，仍以唐代相关区域为主；优先补齐关中、河南、河北、河东、山东、江淮与蜀地的空间节点 | **1–3 工程人日**：完善批量导入检查、分期可见性、名称检索、标签分级与必要的布局调整；沿用 JSON，不增加数据库依赖，按小批次接入 | 有基础来源时约 **3–6 数据人日**。每条核对当期名称、对象含义、资料出处和现代对应地区；若只能确认地区，继续标近似位置。不能以“现代城市存在”为由填满所有朝代的 periodIds |
| **二级：扩展地区与名称版本** | 在第一批质量和标注密度验证后，再增加 **50–80 个**入口，按地区或历史时期逐批交付；补重点城市的名称沿革、治所迁移及来源差异 | **4–8 工程人日**：可重放导入、来源追踪、批次校验、搜索排序和按缩放显示；可见点位增加后再决定是否从 DOM 标记迁移到地图数据图层 | 先预留 **12–30 数据人日**，以首批 10 条的实测速度重新估算。精确遗址定位、城墙范围与复杂迁城个案额外核算，不包含在普通地区入口批次中 |

两级批次的数量是排期边界，不是已取得的资料。可并行做工程与史料核对，达到条件的子批次先交付；不把工程程序准备好等同于全部城市已经考证完成。

### 首批城市的资料清单与入库规则

1. 用已采集的《资治通鉴》《旧唐书》卷级快照和可继续核查的原文，列出候选地名、出现年代、事件语境与实体含义。原文能支持城名出现，不自动支持精确坐标或行政边界。
2. 参考已知 [TGAZ 数据集](https://doi.org/10.7910/DVN/H3OB28) 与 [项目仓库](https://github.com/cga-harvard/tgaz) 的记录结构，先抽 10 条核对有效时间、原始 ID、上游来源和许可；尚未澄清适用条件的数据不能直接批量再发布。
3. 为每个候选填写“历史名、历史对象、有效时期/精度、现代对应地区、坐标来源/精度、史料引用、名称核对状态”。历史地点与现代城市的关系允许一对多、迁移或尚不确定。
4. 新增记录只关联有依据的历史时期；未核定名称不补造整条朝代沿革。输入别名、现代名和当期历史名均应能找到同一地区入口，同时保留所选时期的合理语义。
5. 每批检查重复实体、同名异地、来源外键、时期可见性与地图位置；抽查所列事实的原文，只有逐条核对过的事实才标为已核对。

## 边界工程与资料周期单独估算

在已有合适几何、元数据及适用授权的前提下，**首个 1–3 面样本约需 3–6 工程人日**：建立独立的历史范围记录、转换与校验、时期筛选、点击来源、缺失状态和验收。现有 `Regime.certainty = schematic` 不能直接包装成已核实范围，应增加能够表达具体来源、有效时间与精度的范围数据合同。

文件调查、许可澄清和史料核对先预留 **3–10 数据人日**作为样本调查投入；外部回应可能数周以上，也可能无法取得适用授权。只有实际查看到文件与依据后，才能判断进一步制图/考证工作量。城市第一批可同时推进，不依赖边界样本最终获批。

优先顺序为：**撤下假边界 → 第一批城市 → 一个可追溯历史范围样本 → 第二批城市与同源范围扩展**。本轮不以动画、平滑轮廓或更多图标替代这些交付。

## 本轮验收重点

- 所有历史时期均不会再显示旧手工政权多边形、标签或可重新打开该图层的开关；选择时期仍能浏览对应地点和事件。
- 页面与后续排期中不再保留“观山河”播放功能；普通时期选择及日期信息可使用。
- 新城市的历史名、时期与来源关联可回查；双名表示地区对应，未误称精确古城定位。
- 历史范围只有在来源、年代、授权和考据说明符合条件时上线；空白年份保持明确的缺失状态。
- 河流、湖泊、山脉与海域继续明确属于现代自然地理背景，不用于充当历史行政边界。
