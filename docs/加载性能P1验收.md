## P1-4 内容版本与长期缓存

按用户确认采用内容哈希方案。`scripts/data-versions.ts` 在 Vite 构建时流式计算每个 `public/data/` 文件的完整 SHA256，同时生成客户端虚拟模块与 `dist/content-versions.json`。共 1,210 个文件，版本表为 137,800 字节；文件未变则版本不变。没有在原始 manifest 或 GeoJSON 中改写 URL，改由统一解析器在真正请求时附加版本，保持全部既有数据产物的字节与生成流程不变。

修改文件与职责：

- `vite.config.ts`、`src/vite-env.d.ts`、`src/main.tsx`：构建插件、虚拟模块类型和启动前版本配置。开发模式使用空版本表。
- `src/lib/resource-url.ts`、`load-json.ts`：统一为已登记的同源资料附加 `v`，保留查询、锚点、请求配置、取消和已有版本；跨域地址及 API 不变。
- App、HistoricalRiverLayer、HistoricalSitesLayer、MountainDetailLayer、MountainShapeLayer、PhysicalGeographyLayer、SongSettlementLayer、TangDetailLayer、TemporalSettlementLayer、HistoricalAtlasViewer：迁移静态 fetch；原始 gzip 解码逻辑不变。
- HistoricalMap、BoundaryComparison：MapLibre `transformRequest` 覆盖 DEM、GeoJSON、栅格和图片源；HistoricalAtlasViewer、TerrainLayer 的原图及本地来源链接也附版本。
- `server/versioned-data.ts`、`server/app.ts`、`server/precompressed-static.ts`：服务启动读取版本表，匹配后才设置一年 immutable。过期、未知或重复 `v` 返回 `410/no-store`，不会把新文件伪装成旧版本，也不回退到 SPA。原文无效 Range 保持 `416/no-store`。
- `scripts/measure-load-performance.mjs` 增加 `--versioned`；新增重复访问及更新资料浏览器验证脚本；README 说明部署次序。

### 部署边界

必须按 **停止服务 → 完整构建／替换完整 dist → 启动服务** 的顺序更新。运行中覆盖文件会导致进程持有旧版本表却读取新文件，不支持这种部署方式。构建时也不能同时改动源资料。旧标签页更新后请求尚未缓存的旧版本会收到 410，需要刷新取得新版本；没有增加旧版资料归档。其他静态托管服务须提供等效规则，不能只复制文件就假设获得相同缓存行为。构建仍有既有的大 JS chunk 警告，属于待确认的 P3 拆包范围。
