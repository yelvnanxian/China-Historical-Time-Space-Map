本次在显示层统一使用简体中文地名。地图标签、行政区搜索、自然地理搜索、悬停与详情标题共享同一组名称解析函数；外文和繁体原值保留在折叠的来源信息中，并继续用于检索。

## 名称与证据

- 唐代陈州的`Yinshui`采用“溵水县”，依据《新唐书》卷三十八陈州条的“溵水”及源记录的所属、年份和位置；没有用现代“商水”替代历史名。
- `Hankuang`采用“浛洭县”；`Ao Zhou`和`楚雄fu1府`从该源记录自身同级中文字段恢复为“隩州”“楚雄府”。
- `Weimo`使用名称对应“濊貊”；部落地区名称按字面译出。原资料的政权分组、行政类型和年份保留，不以译名修订史实。
- 13条“奴ㄦ干、失ㄦ兀赤、塔ㄦ河、忽ㄦ海、甫ㄦ河、虎ㄦ文、海剌ㄦ”等记录，原始DBF中文字段使用注音符号“ㄦ”，其同记录拼音明确写作`er`。只对这些已核查的原始编号做“ㄦ→儿”转写，再转简体。来源年份的疑点仍沿用原图层警示。
- 同拼写地名按完整记录编号与原值核对。例如老挝`Ou`对应“南乌河”，浙江`Ou`对应“瓯江”；印度`Son`对应“松河（印度）”，没有误用法国索恩河；泰国`Yom`对应“永河（泰国）”，没有误用法国永河。
- “南俄水库”和“洞里萨河”由已核对的中文专名及源资料对象类型组合译出，映射明确标记为组合翻译。没有恢复南俄水库源资料中错配的墓地名称。

候选名文件是研究记录，不直接作为浏览器标签使用。发布映射包含原值守卫、中文显示名、采用方式、来源URL、证据快照路径和说明。维基百科证据保留具体修订版及响应SHA-256；Wikidata检索响应保留抓取时间、URL、实体编号和SHA-256。它们是名称核对资料，不视为所有历史地理结论的权威依据。

## 待核定条目

完整清单位于`data/evidence/place-name-localization/localization-audit.json`。包括来源拼写或几何存在歧义的`Quan`广西河段、`Hudi`、`Krong`、编号967的`Di’er Songhua`，以及尚未取得足够中文名称依据的部分境外支流。公开界面提供中文待核定名称，折叠保留原文；仍可用原名搜索、定位和查看原始几何。

`Ejia`没有依据现代“𥔲嘉镇”倒推明代县名。检索到的《明史》在线文本存在“柷嘉”等异文，当前证据不足，故保留待核定状态。

## 原始数据与复现

未修改历史边界、古今对照、自然地理交互数据和山系走向原始资产。审计记录保留30份输入文件的SHA-256；既有自然地理与山系来源哈希检查继续通过。

```sh
python3 scripts/build-place-name-localizations.py
npx tsx scripts/audit-place-name-localization.ts
npm test
npm run build
```

构建只读已提交的候选与证据，不联网。全量审计与浏览器共用`shared/boundary-labels.ts`及`shared/place-name-localization.ts`，输出`data/evidence/place-name-localization/display-audit.json`。名称缓存也再次经过稳定的简体转换，覆盖“於潜县、金谿县、劄佐长官司、慈谿县”等残留。

`scripts/fetch-place-name-sources.py --offline`可重建研究索引；联网抓取属于额外的证据更新步骤，不是构建依赖。新增证据必须再次核对具体对象和地理位置，不能仅因为中文词条存在或发生重定向就接受译名。
