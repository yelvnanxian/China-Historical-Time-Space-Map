# 宋代同期治所接入

本轮将 CHGIS V6 官方时序治所点按 **1200 年**筛选为独立图层。地图新增 **1560 条来源记录**，用于放大后查看府州、县及其他原始行政类型的定位资料。点坐标直接来自官方 WGS84 `POINT` 图层，不来自 Hartwell 行政面的标签位置、中心点或现代城镇补点。

“宋代同期”是时间入口，不表示所有记录属于南宋。资料也包含金及其他同期地区；未逐条核定的政权、治所、范围和定年会保留说明。

对应 `county-metadata.json`、`prefecture-metadata.json`、`CHGIS_V6_README.txt` 和日期规则资料保留在同一归档目录。构建时先核对元数据中官方文件的 MD5；发布清单同时记录源包、元数据、宋代建置研究包及两个1200年边界模型的 SHA-256。原始声明和来源署名保留，不由本脚本改写。

## 筛选与隔离

仅选择满足 `BEG_YR <= 1200 <= END_YR` 的来源记录，再核对名称、日期规则和坐标。

| 源文件分组 | 1200年候选 | 发布 | 隔离 |
| --- | ---: | ---: | ---: |
| 县级源文件 | 1298 | 1209 | 89 |
| 府州级源文件 | 368 | 351 | 17 |
| 合计 | **1666** | **1560** | **106** |

106条隔离记录包括：

- **104条坐标冲突**：SHP点与同一DBF记录的 `X_COOR`、`Y_COOR` 最大差值超过0.02度。两套原值均进入审计，不猜选其中一个，也不借现有城市目录坐标补入。邯郸县源编号 `44847` 属于此类。
- **2条日期规则冲突**：遂宁府 `211182`、阆州 `211283` 的日期规则含 `9`（单年切片），但起讫年不同。保留原记录，暂不上图。

构建器还会隔离无效经纬度、缺失或混入未核定外文的中文名称，以及缺失、非整数、逆序的起讫年。本轮另记录全源28条无法判断有效区间的日期记录；它们没有进入1666条1200年候选，不能重复计入106条候选隔离数。

DBF与SHP按原始记录索引逐条对齐，检查点几何类型及记录号。发布几何仅舍入至六位小数，同时保留未舍入双精度坐标、DBF坐标、完整原字段和源索引。显示名称、类型、今录位置转为简体中文；`sourceName` 与 `sourceRecord` 保留原文。

## 定年与同名处理

| 定年分组 | 数量 | 含义 |
| --- | ---: | --- |
| `specified-endpoints` | 881 | 起讫端点规则明确到年、月或日；仍未逐年独立核验 |
| `broad-endpoints` | 112 | 至少一个端点按朝代、跨朝代或年号时段约定 |
| `incomplete-date-rules` | 567 | 至少一个端点规则缺失或未定义；仅按原始起讫年筛选 |

地图详情统一称“1200年时序候选”，显示来源存续年、起讫规则及该分组的限制。规则缺失的记录并没有被补造为精确日期；明确端点也不能证明全年持续存在。

共有 **50组同名同类型记录**。原始记录号保持独立，不因名称、距离或相同坐标合并。例如：

- 山阴县同时有今山西与今浙江两条记录，搜索结果分别显示今录位置与源编号。
- 宁远县、永康县等保留不同地区的同名条目。
- 隩州等在原始时间区间内有重叠记录，仍分别保留，并提示可能是异地同名或时序重叠。

`level` 表示源文件分组，`subtype` 表示该记录的实际类型。县级源文件中有羁縻州、赕、部、城等；府州级源文件中也有军、郡、监等，不能把文件内全部对象统一称为县或府。

## 20条辖区身份关联

时序点源字段没有政权及上级隶属。本轮仅对逐条检查过的 **20条记录**建立文献身份关联：核对固定源编号、原名、实际类型、原始今录位置，再引用已经核验的建置史料，关联1200年同级模型。没有批量同名连接、最近点连接或以空间包含关系推断政权。

- 府州级18条：大同府、济南府、开封府、河南府、重庆府、京兆府、襄阳府、鄂州、江陵府、泉州、福州、庆元府、建康府、临安府、平江府、隆兴府、广州、扬州。
- 县级2条：平晋县、临淄县。

这些点的 `boundaryId`、`researchEntryId`、`catalogPlaceId` 与关联依据均可追溯；其余 **1540条**不填写推测政权，也不假配参考范围。地图可以查看这些点的来源记录，而没有“查看辖区”的误导入口。

以下既有问题继续保留区分：

- 临安府不关联同名临安县；平江府、庆元府不关联异地同名县。
- 晋阳目录入口的同期县级建置对应平晋县，不把太原府当作该县范围，也不更改目录的旧城参考坐标。
- 重庆府治所点按CHGIS原名显示；关联模型原名仍是渝州，模型旧称、层级与1189年升府的年代冲突继续说明。
- 大同府治所点原始类型是府；模型中的“大同府州”及 `Zhou` 类型冲突不会反过来污染治所点类型。

完成文献身份关联后才计算点是否在模型内，这只是数据一致性诊断，不参与挑选辖区。20条CHGIS点本轮均落在已关联模型内；不能据此认定边线或古址正确。泉州原有城市目录参考点仍在模型外，新接入CHGIS泉州点位于模型内，两种参考点分别保留，未以新点暗改旧目录。

## 地图与点选行为

- 府州级源点从 **6级**显示；县级源点从 **8级**显示。按离散档位更新集合，缩放过程中不逐帧重复提交全量原始记录。
- 标签按视野避让，最多显示100个；标签隐藏不会删除对应来源点。绘图数据仅保留几何、ID和源层级，完整证据留在详情数据中。
- “城池”和“全部”允许点选与显示治所名称；切换“山川”或“河流”关闭治所名称、点击和详情，点形淡化为背景。自然地理仍按其图层显示，不因点选筛选被删除。
- “全部”中的具体山川河湖按统一命中规则优先处理；空白行政区域和治所点击分别处理，防止一次点击打开多个详情。
- 搜索支持古名、源中文名称、今录位置和源编号。有输入时检索全包，留空时列当前视野；同名结果以今录位置和源编号区分。
- 选中治所可看定年、原始字段与来源。已核关联条目可查看参考范围或进入城池文献档案；没有关系的点直接说明资料缺口。
- 此图层仅用于宋代1200年入口，不把它显示为唐代、明代治所。1080年北宋辽行政模型仍是另一份年份资料，不会把本包改称1080年点。

## 文件与离线重建

| 文件 | 用途 |
| --- | --- |
| `shared/song-settlements.ts` | 时序点、来源与清单类型 |
| `scripts/build-song-settlements.py` | 离线筛选、校验、人工身份关联与审计输出 |
| `public/data/song-settlements/settlements-1200.geojson` | 1560条地图与详情记录 |
| `public/data/song-settlements/manifest.json` | 数量、分类、限制、来源及输入哈希 |
| `data/evidence/song-settlements/selection-audit.json` | 隔离原值、日期异常、同名组、关联依据及输出哈希 |
| `server/song-settlements.test.ts` | 独立读取原始ZIP、DBF及SHP的回归验证 |

依赖为 **Python 3标准库、Node.js及项目已安装的npm依赖**。Python脚本自行读取ZIP/DBF/SHP，不需要 `shapefile`、`shapely`、GDAL或联网。简体转换使用项目现有 `opencc-js/t2cn`，边界研究构建使用项目现有 `tsx`。

在仓库根目录执行。若修改了城市目录或宋代建置研究，应先更新建置研究包，再生成治所包，避免输入哈希过期：

```sh
npx tsx scripts/build-song-boundary-research.ts
python3 scripts/build-song-settlements.py
npx tsx --test server/song-settlements.test.ts server/song-settlement-display.test.ts
npx tsc --noEmit
```

脚本只读取已归档源包及模型，输出本包和审计文件。未修改源边界、原始坐标、唐明资料或城市目录。

## 验证与边界

六项数据测试独立读取官方ZIP中的DBF和SHP，逐条验证1560个发布点、106条隔离记录、名称、坐标、日期、原始字段、同名保留和20条文献关联，并校验所有输入及输出哈希。显示逻辑另验证宋代隔离、6/8级显示、视野搜索和同名结果。

这批资料提高的是可查询的历史治所密度，不等于重建了宋代所有城镇。CHGIS原始定位仍需地方志、历史地图及考古资料互证；字段一致、点落在参考面内、源日期覆盖1200年，均不是精确古址或真实辖界的独立证明。
