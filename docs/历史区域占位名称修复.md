# 宋金1200年“00”标签的来源与修复

截图山东西部的“00”是原始GIS名称字段中的占位符，经导入、繁简转换和古今对照缓存一路传到了地图。不是地图字体缺字，也不是坐标渲染异常。

已在25个历史图层、12,111个区域中核查显示名称及源名称字段。直接显示的占位名称只有1条；另有7条Hartwell中文原名为空但已有有效拉丁源名回退，以及2条CHGIS源名称全空但已有“原图未命名”说明。没有把这些已说明的未命名区域改成猜测地名。

## 唯一直接受影响的区域

| 项目 | 原始值 |
| --- | --- |
| 应用ID | `hartwell-1200-province-v5_1200_chin_chn_1200_l-19` |
| 数据集 | Hartwell 1200，省/路等同层单位 |
| 来源 | [CHGIS V5 Hartwell，DOI 10.7910/DVN/29302](https://doi.org/10.7910/DVN/29302) |
| 原DBF | `v5_1200_chin_chn_1200_l.dbf`，Big5编码 |
| 原记录 | `CHN1200L_I=19`，零基行号18 |
| `CODE` | `J003200000000` |
| `H_PINYIN_N` / `H_UNICODE_` | 都是`00` |
| `H_ADMIN_TY` | `21` |
| `H_SUP_PROV` / `H_SUP_CHPV` | `Dongping Fu` / `東平府` |
| `H_PROVINCE` / `H_CHINPROV` | `Fu` / `Jin dynasty` |
| 代表点 | 经度116.6440109821182，纬度35.66110909856509 |

原行的名称、行政类型、上级等字段明显与正常模式不符。不能把`H_SUP_CHPV=東平府`直接当作整个区域的名称。

导入器`normalize_name()`此前只把空值或解码替代符作为异常，`00`是非空字符串，因此被保存为`name`。古今对照的`historicalName`、`simplifiedName`也都是`00`；OpenCC不会把数字变成名称。现代空间对应“山东 / 济宁市”本身没有这一问题，它仍仅表示代表点落点。

## 为什么可以恢复为“山东西路”

恢复依据来自同一份原始GIS，未凭截图或现代位置猜名：

1. 受影响省级面编码为`J003200000000`。
2. 同年府/州层中有10条`CODE`以`J0032`开头的记录，分别为東平府、徐州、邳州、滕州、博州、兗州、泰安州、曹州、濟州、德州。
3. 这10条记录的上级中文字段`H_CHINPROV`一致为`山東西路`，英文`H_PROVINCE`一致为`Shandong Xi Lu`。
4. 使用原始EPSG:2333几何比较，该10面并集与受影响省级面交并面积比为 **0.9999999999035787**。原面约55,346.878357平方公里，对称差仅约5.33662平方米，是数值运算量级的差异。

因此该面属于同源数据中的“山東西路”，简体显示“山东西路”。東平府只是这10个下级记录之一。

部分原几何无效，集合运算时仅在内存中`make_valid`以完成比较。没有重写原始ZIP、历史GeoJSON、原始名称或边界坐标，也没有把面积比较当作史学上重新核定边界。

完整原行、10条子记录、源文件SHA256和几何计算结果见`data/evidence/boundary-labels/placeholder-audit.json`。

## 实现与接入

新增：

- `shared/boundary-name-corrections.json`：只包含这一条有证据支持的显示名称补丁，保留原始名、源ID、编码、年份及来源链接。
- `shared/boundary-labels.ts`：统一的名称检测与显示解析。
- `server/boundary-labels.test.ts`：5项回归测试及全量显示名检查。

根组件生成`displayRegions`时统一调用：

```ts
const match = correspondences?.entries[feature.properties.id];
const display = getBoundaryDisplayLabel(feature.properties, match?.simplifiedName);
const properties = { ...feature.properties, ...display };
```

返回值：`name`、`originalName`、`nameStatus`、可选`nameCorrectionNote`及`nameSourceUrl`。此记录得到`name="山东西路"`、`originalName="00"`、`nameStatus="source-recovered"`。地图标签、搜索结果、选中详情均应读取同一份`displayRegions`的名称。

**必须让解析器的结果优先于`match.simplifiedName`。** 古今对照继续保留原始`00`供审计，不能在解析完成后又用缓存字段覆盖显示名。详图可显示`nameCorrectionNote`，并把`originalName=00`明确标作原始字段；这不是恢复后的地名。

该行其他原始分类字段也存在错位，详情中的“来源分组：東平府”“原始类型：21”应被视为异常源字段，不宜再推导真实上级或行政建制。本次工具只恢复有证据支持的名称，其余字段仍保持原样。

## 对其他异常值的处理

- 空值、纯数字代码、全角`００`、明确的`N/A`等哨兵会被识别为占位名称。
- 只根据区域ID及匹配的原始名、来源、编码、年份应用已核实补丁，不把所有`00`统一改成山东西路。
- 当名称为空但本区域自身的`sourceName`、`NAME_CH`、`NAME_FT`或`NAME_PY`有有效值时，可以使用该源字段。
- 不把父级/上级字段或现代地名提升为缺失的历史名称。
- 无足够证据时显示“来源未命名区域 · 记录ID”。
- `Nan`是原数据中“南州”的有效拼音，必须保留，不能因大小写不敏感的`nan`检测误判为数值`NaN`；已专门加入回归测试。

原始Hartwell DBF名称复核覆盖全部9,365个已导出的Hartwell记录：7条`H_UNICODE_`为空，1条`H_UNICODE_`及`H_PINYIN_N`为`00`。CHGIS另外2条源名全空已在前次导入中说明。完整ID与分类均写入审计JSON。
