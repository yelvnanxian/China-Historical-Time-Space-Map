# 唐代郡州辖区关联

755年CHGIS治所点与741年Hartwell行政模型是不同来源和年份。本次保留两者的原始几何，在 `public/data/tang-boundary-crosswalk.json` 发布显式对应关系。郡、州和府按同一行政层级处理；高亮始终使用741年参考面，不将其改称755年核定疆界。

目前关联1,243条历史治所记录和91个精选城池入口，其中212条治所有明确的来源改名链。未能核实的记录进入 `data/evidence/tang-detail/boundary-crosswalk-audit.json`，不按最近距离推定归属。

## 证据规则

1. 741年治所必须与州面或县面同名，且原始治所点位于该模型面内。繁简和行政通名用于名称规范化；不使用拼音近似或最近点。
2. 县治的州级归属取县面原始 `sourceHierarchy` 中政权、省道、府州字段，须唯一对应州面。
3. 755年沿用同一CHGIS `SYS_ID` 的记录直接复用其741对应；发生改名时，要求前后记录原始点几何完全相同、起讫年连续，且新记录 `BEG_CHG_TY` 明确为“更名”。同址但年代有空缺、发生迁治、歧义或缺少前序记录时不关联。
4. 精选城邑使用目录中的唐代名或主名与已核实治所或模型记录对应，同时检查目录近似定位落在州级面内。一般别名列表可能混有后世名称，不用于推定。对于长安等未保留可用CHGIS县治的入口，只使用同名Hartwell县记录明确的州级隶属，不把近似城市点当成精确县治。

例如定襄郡的CHGIS记录始于742年，前序忻州止于741年、来源注明更名且点几何完全一致，因此关联忻州的741模型。这个证据支持行政单位名称关联，不证明期间边界未变。

## 许州和徐州的源名称问题

Hartwell741州级记录33的名称为“徐州”，但省州隶属字段为“許”、下属8个T0012000031编码县含许昌及长社，且CHGIS许州点在本面内。记录35正好相反，其7个T0012000033编码子县含彭城、萧县，CHGIS徐州点在本面内。本次通过 `shared/boundary-name-corrections.json` 显式纠正显示名，保留原名称、来源记录与几何，审计记录附同源子县和治所证据。

## 地图交互契约

行政背景层级始终随缩放切换，查找辖区不会锁死层级。选中区域以独立图层保留高亮，缩放至其他层级仍可辨认选中州域。关闭行政边界、切换到不能点选行政区的模式或主动选择其他对象时清除该选择。

`HistoricalBoundaryLayer` 接受 `selectionRequest: { id, requestId, focus?, quiet? }`。每个请求只消费一次，等当前数据集的边界资料加载完成后生效。默认定位并通知选择回调；`focus: false` 不改变视野，`quiet: true` 不调用 `onSelection` 或 `onRegionSelect`，适合点击郡/城市时保留其资料卡并同步高亮辖区。`onRegionSelect` 回传完整 `BoundarySelection`。

如果等待加载期间选中了另一对象，`resetKey`改变而请求标识未变，则取消旧请求；同批更新携带新请求时保留新目标。这样已关联郡A切换到未知郡B后，A不会在加载结束时错误补画。切换数据集同样取消上期未完成请求；数据完全加载后仍查不到的boundary id会清除旧高亮，不猜测替代面。

交互模式为 `cities | mountains | rivers | all`。行政轮廓始终按缩放显示，只有cities/all生成行政名称、接受区域点击和搜索。all模式先尊重DOM名称按钮和 `originalEvent.defaultPrevented`，再通过共享 `findNaturalMapHit` 判断自然对象；已有自然命中时让出，消除事件监听注册顺序造成的抢选。

## 重建与验证

运行 `npx tsx scripts/build-tang-boundary-crosswalk.ts` 重建发布表和审计。输入文件哈希随表记录；治所、原模型、名称纠正或目录发生变化后需要重建。运行 `npx tsx --test server/tang-boundary-crosswalk.test.ts server/boundary-labels.test.ts server/boundary-selection.test.ts` 检查真实点面、改名链、源隶属关系、名称修正和异步请求时序。
