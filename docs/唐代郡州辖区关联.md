# 唐代郡州辖区关联

755年CHGIS治所点与741年Hartwell行政模型是不同来源和年份。本次保留两者的原始几何，在 `public/data/tang-boundary-crosswalk.json` 发布显式对应关系。唐代的郡、州和府属于县之上的同一行政层级；755年郡与县不是同一级，也不应理解成所有郡都统辖另一级州。高亮始终使用741年参考面，不将其改称755年核定疆界。

当前发布的755年 **1,682个治所点中，1,024个已关联、658个未关联**。统计如下：

| 755年点类型 | 总数 | 已关联州级参考面 | 未关联 |
| --- | ---: | ---: | ---: |
| 府州层记录 | 317 | 232 | 85 |
| 县级记录 | 1,365 | 792 | 573 |
| 府州层中的郡 | 260 | 214 | 46 |
| 府州层中的州 | 45 | 15 | 30 |
| 府州层中的府 | 4 | 3 | 1 |

府州层另有8条南诏、周边单位等来源分类记录，均未关联。表中郡、州、府是317条的子集，不应与前两行相加。完整映射表包含 **1,269个跨年治所ID**，其中245个仅供741年等辅助身份核查；不能把1,269当作755年可见治所数。精选城池入口另有91个已关联，13个未关联。

本轮新增17个755年府州层关联，另补9个仅用于741年的ID。此前1,243条是跨年ID总数，当时755年实际只有1,007个已关联点。所有缺口、原因分组、补充链及统计进入 `data/evidence/tang-detail/boundary-crosswalk-audit.json`，不按最近距离推定归属。

## 证据规则

1. 741年治所必须与州面或县面同名，且原始治所点位于该模型面内。繁简和行政通名用于名称规范化；不使用拼音近似或最近点。
2. 县治的州级归属取县面原始 `sourceHierarchy` 中政权、省道、府州字段，须唯一对应州面。
3. 755年沿用同一CHGIS `SYS_ID` 的记录直接复用其741对应；发生改名时，要求前后记录原始点几何完全相同、起讫年连续，且新记录 `BEG_CHG_TY` 明确为“更名”。同址但年代有空缺、发生迁治、歧义或缺少前序记录时不关联。
4. 精选城邑使用目录中的唐代名或主名与已核实治所或模型记录对应，同时检查目录近似定位落在州级面内。一般别名列表可能混有后世名称，不用于推定。对于长安等未保留可用CHGIS县治的入口，只使用同名Hartwell县记录明确的州级隶属，不把近似城市点当成精确县治。
5. 模型源名称可能较晚，不能只要求741年点名已匹配才允许755年记录关联。补充规则读取原始府州时序数据：存续期与618—907年相交、点坐标自洽，连续记录必须使用**完全相同的未舍入SHP坐标**、相同`LEV_RANK`、起讫年连续、前后双方变更类型都为“更名”、日期规则明确到年或更细、前后候选双向唯一。坐标冲突隔离记录仍参与歧义检查，但不得进入关联链。可达名称必须只对应一个包含原始治所点的具名模型面；绝不单独根据包含关系或邻近距离定身份。

例如定襄郡的CHGIS记录始于742年，前序忻州止于741年、来源注明更名且点几何完全一致，因此关联忻州的741模型。这个证据支持行政单位名称关联，不证明期间边界未变。

## 江陵与同类源名称错期

江陵县此前已有辖区，江陵郡却没有，原因在旧关联规则：741年CHGIS叫“荆州”，Hartwell741模型记录94却叫“江陵府”。首轮名称匹配失败，755年江陵郡又只能继承已匹配的前身，因而被漏掉。原始CHGIS府州点提供了可复核的连续更名链：

| SYS_ID | 名称 | 起讫年 |
| --- | --- | --- |
| 34443 | 荆州 | 621—741 |
| 34442 | 江陵郡 | 742—757 |
| 34441 | 荆州 | 758—759 |
| 34437 | 江陵府 | 760—1129 |

这四条未舍入SHP坐标完全一致，前后更名字段、连续年份明确。现将荆州、江陵郡、江陵县以及精选江陵入口关联到同一个原始模型面94。**“江陵府”仍标为模型源名；CHGIS这条府名记录始于760年，不是755年的称谓。** 江陵县的独立来源SYS_ID为43676，县模型664原始隶属字段为“山南／江陵”，其县治不是郡辖区面中心推算出来的。

同类补充包括蜀郡→成都府、洪源郡→黎州、缙云郡→处州、潭阳郡→叙州、晋康郡→康州、龙水郡→宜州等。名称链的每一步、实际起讫年和模型名称锚点保留在发布关联的 `nameChain`、`modelNameAnchor` 中。完整原始证据位于 `data/evidence/tang-detail/chgis/tang-prefecture-name-records.json`：1,488条可核查记录、70条坐标冲突隔离记录，来源仍是已归档CHGIS官方ZIP，未另行补画边界。

## 许州和徐州的源名称问题

Hartwell741州级记录33的名称为“徐州”，但省州隶属字段为“許”、下属8个T0012000031编码县含许昌及长社，且CHGIS许州点在本面内。记录35正好相反，其7个T0012000033编码子县含彭城、萧县，CHGIS徐州点在本面内。本次通过 `shared/boundary-name-corrections.json` 显式纠正显示名，保留原名称、来源记录与几何，审计记录附同源子县和治所证据。

## 地图交互契约

行政背景层级始终随缩放切换，查找辖区不会锁死层级。选中区域以独立图层保留高亮，缩放至其他层级仍可辨认选中州域。关闭行政边界只隐藏轮廓，重新开启可恢复已选辖区；切换到不能点选行政区的模式或主动选择其他对象时清除该选择。

`HistoricalBoundaryLayer` 接受 `selectionRequest: { id, requestId, focus?, quiet? }`。每个请求只消费一次，等当前数据集的边界资料加载完成后生效。默认定位并通知选择回调；`focus: false` 不改变视野，`quiet: true` 不调用 `onSelection` 或 `onRegionSelect`，适合点击郡/城市时保留其资料卡并同步高亮辖区。已关联的府州治所首次选择用quiet:true、focus:true框出整个参考辖区；筛选切换只重画高亮，不再次调整视野。`onRegionSelect` 回传完整 `BoundarySelection`。

关联表 `coverage` 只统计755年已发布点，`auxiliarySettlementLinks` 单列辅助ID；`unmatchedSettlements` 给每个当前缺口提供 `reasonCode`、说明及候选模型ID，不能把未核定关联显示成“这个郡没有辖区”。新增 `documented-model-name-chain` 表示通过上述原始更名链确认单位身份。

县治与县模型的点面一致性另见[唐代县治与模型面冲突审计](唐代县治与模型面冲突审计.md)。该诊断与父州关联分开：唐城县、湖北吉阳县本无crosswalk关联，原始点却在同名县模型之外；模型因此只作为诊断参照，不移动点或重画县界。

如果等待加载期间选中了另一对象，`resetKey`改变而请求标识未变，则取消旧请求；同批更新携带新请求时保留新目标。这样已关联郡A切换到未知郡B后，A不会在加载结束时错误补画。切换数据集同样取消上期未完成请求；数据完全加载后仍查不到的boundary id会清除旧高亮，不猜测替代面。

交互模式为 `cities | mountains | rivers | all`。行政轮廓始终按缩放显示，只有cities/all生成行政名称、接受区域点击和搜索。all模式先尊重DOM名称按钮和 `originalEvent.defaultPrevented`，再通过共享 `findNaturalMapHit` 判断自然对象；已有自然命中时让出，消除事件监听注册顺序造成的抢选。

## 重建与验证

运行 `/tmp/map-chgis-runtime/bin/python scripts/extract-tang-prefecture-name-records.py` 从归档ZIP重提名称证据（新环境使用安装了`pyshp`的Python），然后运行 `npx tsx scripts/build-tang-boundary-crosswalk.ts` 重建发布表和审计。正常重建不访问网络。输入文件哈希随表记录；治所、原模型、名称纠正或目录发生变化后需要重建。

运行 `npx tsx --test server/tang-boundary-crosswalk.test.ts server/tang-detail.test.ts` 检查真实点面、来源ZIP内DBF与未舍入SHP的逐条一致、连续更名链、源隶属关系、全部755统计与未关联保护。`server/boundary-labels.test.ts`、`server/boundary-selection.test.ts` 另检查名称修正和异步请求时序。
