# 加载性能 P2-1 验收

本阶段只处理边界几何的可追溯修复和坐标体积优化。原始 `public/data` 保持不变，构建时复制到 `artifacts/production-build-*`，在副本中生成修复几何，再由 Vite、版本哈希和预压缩继续生成 `dist`。

## 处理规则

- 原始无效 Polygon / MultiPolygon 使用 GEOS `make_valid(method="linework")` 修复；不删除要素，不修改 ID、名称、来源字段、上下级字段或 `labelCoordinates`。
- 坐标按十进制向零截断到 5 位；相邻重复点去重，环闭合后重新验证。
- 截断造成自交或退化时再次修复并记录原因。极小面如果五位网格会变成无效环，则保留该要素的修复后原精度，避免制造空面；报告中标为 `precisionException`。
- 每层报告源 SHA256、输出 SHA256、面积变化、最大坐标位移、修复阶段和异常要素。修复后的几何只代表可渲染的近似面，不能被解释为新的历史考证。

## 结果

本次生产构建处理 25 层、12,111 个边界要素：

| 指标 | 结果 |
| --- | ---: |
| 原始边界正文 | 166,137,008 B |
| 修复后边界正文 | 108,004,954 B |
| 原始 gzip 合计 | 60,421,789 B |
| 修复后 gzip 合计 | 32,267,851 B |
| 原始无效面 | 58 |
| 发生修复的要素 | 105 |
| 五位网格无法安全表达、保留修复后原精度 | 8 |
| 最大坐标位移 | 1.519855 m |

默认唐 741 年国家＋道层：

| 指标 | 原始 | 修复后 |
| --- | ---: | ---: |
| 正文 | 2,935,675 B | 1,553,969 B |
| Brotli | 1,086,996 B | 482,415 B |
| gzip | 1,241,432 B | 530,662 B |

修复后的 25 层、12,111 条记录与原始资料逐条比对，名称、来源、年份、上下级、搜索顺序、古今对照和标签坐标全部一致；索引 bbox 与新几何一致。浏览器回归覆盖搜索未加载县、上下级跳转、切年、双图比较、城池辖区和历史原图，10 项全部通过。

## 构建与验证

首次使用需创建隔离 Python 环境：

```sh
npm run setup:geometry
npm test
npm run build
npm start
```

构建报告写入 `artifacts/performance/p2-precision-report.json`。生产构建失败会保留上一份 `dist`；不要在服务运行期间覆盖 `dist`。`MAP_GEOMETRY_PYTHON` 可指定已安装 Shapely 2.1.2、pyproj 3.7.2 的 Python。

## 未包含的内容

本阶段没有做 coarse / fine 多级几何、共享边拓扑简化或属性裁剪。P2-2 和 P2-3 仍需单独设计、测量和回归。
