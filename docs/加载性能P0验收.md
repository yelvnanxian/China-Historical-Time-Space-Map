# 加载性能 P0 验收

测量日期：2026-11-07。基线：`b65f563`，应用版本仍为 0.21.0。本轮只实施 P0-1、P0-2，后续 P1/P2/P3 等用户确认。

## 测量口径与基线

所有网络测量均先 `npm run build`，再 `npm start`，访问 `http://127.0.0.1:3001`，未使用 Vite dev。文件大小由 `scripts/measure-load-performance.mjs` 递归统计；正文下载字节取 curl `size_download`，未用 Content-Length 推算。MB 为十进制 1,000,000 字节。

| --- | ---: |

| 7 个年份、25 份边界层正文合计 | 166,137,008 |
| 默认唐代所用 741 年全部 4 层 | 23,360,566 |
| 741 年 country 层 | 323,593 |
| modern-correspondence：12,111 条 | 12,808,847 |
| 主 JS / worker / CSS | 1,741,627 / 510,405 / 197,198 |

基线带 `Accept-Encoding: br,gzip` 仍返回明文；assets、index、data 均为 `public, max-age=0`，带 ETag。

与任务参考的差异：1820 年仅省、府两层，10,382,238 字节；1911 年仅省、府、县三层，34,992,678 字节。并非每套数据都有四层，也并非全部在 22–33 MB 内。本轮未补造缺失层。

首屏从不带参数的 `/` 打开，全新 Chrome context、1440×900、保留初始引导，等待网络空闲、2 秒和再次空闲后记录 HAR。应用自身会更新 URL；没有预置选城或缩放状态。请求数包括重验证及 Worker。耗时含等待和截图，不据此声称首屏渲染加速倍数。

发现 Playwright HAR 漏计 Worker 正文：基线 HAR 为 53,206,694 字节，同期 curl 实测 Worker 为 510,405 字节，修正总计 **53,717,099 字节**。优化后脚本直接保留 Resource Timing，仅为已确认未缓存、非条件请求且 HAR bodySize=0 的 Worker 补 `encodedBodySize`；不使用 Resource Timing 估算的响应头大小。重复资源的 304 或缓存响应不补正文。原始 HAR 和补正字段均保留，早期口头报告的 53.21 MB 是未补 Worker 的值。

## P0-1：预生成 Brotli / gzip

采用构建后预压缩：大文件只在构建时压缩，服务期间直接读取副本。Brotli quality 6、gzip level 9，限制两个生成 worker。仅为 JSON、GeoJSON、JS、CSS、SVG、TXT 生成有体积收益的副本；小文件无收益则不生成。HTML 仅 644 字节，仍原样提供。

文件变动：

- `scripts/precompress-static.mjs`：生成 dist 内 `.br`、`.gz`，不改原文件、图片、已有压缩文件。
- `server/precompressed-static.ts`、`server/app.ts`：在静态服务前按 Accept-Encoding 协商，保留 MIME、Vary、HEAD、ETag、304、Range；同权重优先 Brotli，不带协商头则返回原文。
- `package.json`、`package-lock.json`：build 接入生成器；声明已由 Express 使用的 negotiator 为直接依赖，并加类型声明，复用标准 q 值解析。应用版本不变。
- `server/static-compression.test.ts`：编码、原文等价、现有 gzip、条件请求、范围、路径及生成器重复运行验证。
- `scripts/measure-load-performance.mjs`：递归盘点、7 个数据集逐层 curl 实测、正文和响应头落盘。
- `scripts/measure-browser-load.mjs`：首屏 HAR、截图、Resource Timing 和统计。
- `scripts/verify-tang-detail-browser.mjs`：浏览器放大唐代长安附近、点浐河、核查 gzip 原字节与详情显示。
- 本文及 README：部署和验收说明。

### 验证结果及成本

- `npm test`：278/278 通过（基线 272 项，新增 6 项）；`npm run build` 含 TypeScript 检查通过。
- 默认页无 pageerror、无失败请求，截图正常；唐代长安定位后放大至 12.5 级，浐河、灞河、锦绣湖等名称出现，点浐河显示原有“现代参照”详情。
- 浏览器实际加载关中概览及两个细节文件，分别 1,403,407 / 128,694 / 38,036 字节，解压为 1,791 / 559 / 246 个 feature；均无 Content-Encoding，gzip 魔数与 dist 原字节一致。
- 逐文件比较 public/data 与 dist/data 的 1,195 个原文件，379,493,449 字节全部一致。未修改数据、前端文案、地图几何、名称或朝代归属。
- 新增 71 份 Brotli、71 份 gzip 副本，共 115,352,127 字节（约 115.35 MB），只占用被忽略的 dist，不增加 Git 历史数据体积。最终 P0-1 完整构建本机约 16.75 秒，受机器和并发测试影响，不作为稳定基准。
- Vite 仍提示主 bundle 超过 500 kB；客户端仍需解析完整 JSON。压缩解决网络体积，不等于减少解压后的内存或渲染计算。

## P0-2：哈希资源长缓存

P0-1 独立提交为 `df9c449`。P0-2 在其后另行提交，只调整生产静态资源缓存策略。

文件变动：`server/static-cache.ts` 统一判断当前 Vite 8 位哈希文件；`server/app.ts` 的静态文件与 SPA 入口接入策略，错误响应清除缓存头；`server/precompressed-static.ts` 使压缩表示使用相同策略；`server/static-compression.test.ts` 增加缓存回归；README 和本文补部署说明。

| 资源 | P0-1 Cache-Control | P0-2 实测 Cache-Control | P0-2 Content-Encoding | curl 正文字节 |
| --- | --- | --- | --- | ---: |
| /assets/index-BwTNrOBk.js | public, max-age=0 | public, max-age=31536000, immutable | br | 454,323 |
| /assets/maplibre-gl-worker-CbRivRi4.js | public, max-age=0 | public, max-age=31536000, immutable | br | 135,724 |
| /assets/index-BQUY8FZw.css | public, max-age=0 | public, max-age=31536000, immutable | br | 31,558 |
| /index.html、/ | public, max-age=0 | no-cache | 无 | 各 644 |
| /explore/tang（SPA 回退） | public, max-age=0 | no-cache | 无 | 644 |
| /data/boundaries/hartwell-1200-county.geojson | public, max-age=0 | public, max-age=0 | br | 3,366,023 |
| /data/modern-correspondence.json | public, max-age=0 | public, max-age=0 | br | 343,520 |

这些响应仍带 ETag；可压缩文本的 identity/br/gzip 均带 `Vary: Accept-Encoding`。无哈希 assets 仍短缓存，404/406/416 不设置一年缓存，API 路由不受影响。上述数值来自 curl 实际下载，而非响应 Content-Length。

最终冷启动依旧 **101 次请求、12,735,681 字节**（原 HAR 12,599,957，加 Worker 135,724），比基线减少 **76.3%**。与 P0-1 相比仅响应头长度略有变化；长缓存主要改善再次访问。

实测同一浏览器 context 中先访问 `/`，关闭该页再新开页面访问 `/`：P0-1 的 JS、CSS、Worker 三个资源均发起 304 重验证；P0-2 三个资源全部使用缓存，Resource Timing transferSize 均为 0，CDP 无对应网络响应头事件。此处只用 transferSize 的零值确认缓存，不使用其非零值估算传输大小。强制刷新或清缓存不属于这一再次访问场景。

`npm test` **281/281 通过**，包含 identity/br/gzip、HEAD/304、HTML/SPA、未带哈希资源、data/native gzip、错误响应和 API；`npm run build` 通过，本机本次约 16.00 秒。默认页再次验证无 pageerror、无失败请求；数据下载字节和 P0-1 相同。

发布注意：完整部署新 dist（含 sidecar），入口会重验证并引用新的哈希名；不要在保持哈希名的情况下替换 JS/CSS 内容。如果改用其他静态服务器，需在该服务器另行配置编码协商和缓存，Express 规则不会自动迁移。新增约 115.35 MB 磁盘占用与构建压缩成本仍然存在；地图原数据、解析开销和未实施的 P1 工作保持原状。

P0-2 原始证据：`artifacts/performance/p0-2-transfer.json`、`p0-2-browser/`、`p0-2-warm-cache.json`，对照再次访问记录为 `p0-1-warm-cache.json`。回滚时先回滚 P0-2，再按需回滚 P0-1，避免后一步对前一步的依赖。

## 复测命令

在项目目录分别运行构建、生产服务；不要以 `npm run dev` 验收：

```powershell
npm run build
npm start
```

另一终端运行（Windows 的 curl 使用 curl.exe，正文落 NUL；macOS/Linux 可用 curl 和 /dev/null）：

```powershell
node scripts/measure-load-performance.mjs --data-root dist/data --output artifacts/performance/current-transfer.json
curl.exe -s -H "Accept-Encoding: br,gzip" -D - -o NUL -w "%{size_download} %{http_code}\n" http://127.0.0.1:3001/data/boundaries/hartwell-1200-county.geojson
curl.exe -s -D - -o NUL -w "%{size_download} %{http_code}\n" http://127.0.0.1:3001/data/boundaries/hartwell-1200-county.geojson
$asset = (Get-ChildItem dist/assets/index-*.js | Select-Object -First 1).Name
curl.exe -s -H "Accept-Encoding: br,gzip" -D - -o NUL -w "%{size_download} %{http_code}\n" "http://127.0.0.1:3001/assets/$asset"
curl.exe -s -D - -o NUL http://127.0.0.1:3001/index.html
curl.exe -s -H "Accept: text/html" -D - -o NUL http://127.0.0.1:3001/explore/tang
```

浏览器工具为独立测量依赖，不加入产品 package-lock。需本机已安装 Chrome：

```powershell
npm install --prefix artifacts/performance-tools --no-package-lock --no-save playwright
node scripts/measure-browser-load.mjs --playwright-module artifacts/performance-tools/node_modules/playwright/index.mjs --output-dir artifacts/performance/current-browser
node scripts/verify-tang-detail-browser.mjs --playwright-module artifacts/performance-tools/node_modules/playwright/index.mjs --output-dir artifacts/performance/current-tang-detail
npm test
```

本轮原始证据在被 Git 忽略的 `artifacts/performance/`：`baseline-transfer.json`、`baseline-browser/`、`p0-1-transfer.json`、`p0-1-browser/`、`p0-1-tang-detail/`。浏览器目录含 HAR、JSON 汇总和截图；报告保留关键数字以便跨机器核对。
